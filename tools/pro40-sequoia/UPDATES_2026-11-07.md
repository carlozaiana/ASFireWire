# November 2026 source update

This update brings the separate Sequoia experiment from the 13 October snapshot
to the source used by the working installation after 19 October. The maintainer
closed ASFW PR #199 on 20 October as outside the DriverKit project's scope. The
fork branch remains a public research record; the PR is not being reopened.

## Speaker assignments and twelve playback channels

`HalSpeakerLayout.hpp` supplies explicit named-channel descriptions and stable
connector names using the proper CoreAudio property selector. Valid speaker and
stereo assignments are normalized, validated and saved through the HAL host's
storage API. Failed writes preserve the previous state; callback code does not
take storage locks. Duplicate named speakers, unsupported labels and out-of-range
channels are rejected. Standard tag/bitmap descriptions are normalized before use.

`DuplexAudioFormat.hpp` defines the 8-input/12-output application geometry used
through HAL, IPC, queues, the native bridge and keep-active. Output samples 1–12
occupy playback stream A's existing twelve PCM slots; its following MIDI slot
and silent stream B retain their original positions. Packet geometry, FireWire
timing, sample rate and audio buffering offsets do not change. Saved 5.1 mappings
remain valid; additional outputs start unassigned. Hardware routing remains the
Pro 40 router's responsibility, not an assertion of twelve analog connectors.

The behavior was checked against the local ALSA Pro40 routing description
(`protocols/dice/src/focusrite/spro40.rs:24–46`) and AM824 slot ordering
(`amdtp-am824.c:99–102,167–173`). Implementations were not copied.

The QuickTime investigation found source/destination label sensitivity. A WAV
mask `0x3f` was read as `WAVE_5_1_B`, with rear-surround labels. A comparison copy
using `0x60f` retained identical audio data and played all six channels with the
device's side-surround-labelled 5.1 layout. The public MatrixMixMap API reproduced
zero surround coefficients between those layouts; QuickTime's internal API path
was not traced. The tested MOV already used matching labels and played correctly.
Older High Sierra/Yosemite QuickTime tests played the original WAV, so the result
does not establish that Nuendo generated an invalid file. `ProbeSurroundMapping.cpp`
is an offline API probe; it does not start an audio device.

## Playback delivery scheduling

An earlier playback queue underrun caused the fail-closed source-loss lifecycle
to withdraw the device. Existing evidence did not isolate which delivery thread
paused. The HAL delivery owner and native bridge owner now request a verified
Mach time-constraint policy after negotiation: 2 ms period, 1 ms computation,
2 ms constraint. Absolute waits bound the loop; an overrun does not trigger a
catch-up spin. Dedicated owners restore and verify the prior standard policy
before exit. This does not change queue sizes or hide missing PCM with silence.

Retained counters describe work/wait margins and the exact rejected queue range
after a fault. No new per-callback or per-packet logging was added. The bounded
600-second hardware run passed, including modest CPU load; its margins are
observations, not guaranteed worst-case scheduling bounds.

## Clock initialization and boot-bound recovery

After use on an older Mac, the interface could be idle and locked at actual
44.1 kHz even while CLOCK_SELECT requested internal 48 kHz. Warm-up now admits
the validated internal 44.1/48 kHz low-rate state and explicitly initializes
48 kHz after ownership. Normal audio admission and successful cleanup remain
strictly 48 kHz. This adds no native 44.1 kHz playback mode.

Linux's `dice-interface.h:91–175` distinguishes desired and actual clock state;
`dice-stream.c:289–301` reselects after ownership and rereads stream geometry.
The established write/notification/readback ordering is preserved.

Each cooperating native worker persists the actual Mac boot UUID and active-file
mtime before hardware entry. `NativeRecovery --after-reboot` holds exclusive
flock and requires different, valid previous-boot provenance before auditing an
unclean lease. It then requires two read-only, stable-generation idle snapshots:
no owner, ENABLE zero, all channels unassigned and supported clock/layout.
Same-boot, missing/malformed or legacy-overwritten provenance stays blocked.
The file is never unlinked/replaced to bypass exclusion. A live holder remains
protected even when its clean marker has already been written.

The login orchestrator waits its existing 30 seconds before registry discovery,
then audits before starting a native worker. It still consumes one attempt per
boot, discards input samples and emits silence. It reports a lease refusal as
pre-entry failure instead of trying to read a native log that was never created.
No native retry loop or automatic same-boot lease reset was introduced.

The earlier October crash involved an obsolete separately installed warm-up
binary. Rebuilding that package brought it onto the teardown-lifetime repair
already present in the public native sources. The new teardown regression checks
exercise that code with fake ports, including late callbacks and protected mappings.

## Reliability statement and scope

On 7 November the owner reported flawless normal use since the 19 October change.
The latest automatic warm-up completed with a clean preflight lease. The controlled
180 s/24 s sessions, successful 44.1-to-48k initialization, persistent stream and
physical observations are detailed in [VALIDATION.md](VALIDATION.md). This is
encouraging one-system evidence; it is not a production release, continuous
multi-day endurance test or systematic sleep/wake/hot-unplug certification.

This publication changes source/documentation in the contribution worktree only.
No working plugin, installed package, audio service or device setting was changed.
Private evidence, identity/signing material, raw media and local recovery scripts
are not included. The public warm-up code uses the same synthetic fixture GUID
as the other exported development tools and is not a portable installation recipe.
